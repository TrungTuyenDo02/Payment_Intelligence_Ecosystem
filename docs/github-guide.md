# Hướng dẫn thao tác GitHub cho dự án

Dành cho chủ dự án và người tiếp quản. Quy ước của dự án: **mỗi việc một nhánh, đi qua pull request (PR), CI xanh mới merge vào `main`**. `main` là bản cuối cùng; lịch sử commit cũ được giữ nguyên.

Repo: <https://github.com/TrungTuyenDo02/Payment_Intelligence_Ecosystem>

## 1. Lần đầu trên một máy

```bash
git clone https://github.com/TrungTuyenDo02/Payment_Intelligence_Ecosystem.git
```

```bash
cd Payment_Intelligence_Ecosystem && cp .env.example .env
```

```bash
make setup
```

`make setup` cài môi trường và bật git hook của dự án (mục 6). Trên Windows, chạy mọi lệnh trong **WSL Ubuntu**.

## 2. Làm một việc mới

1. Lấy `main` mới nhất:

   ```bash
   git checkout main && git pull
   ```

2. Tạo nhánh. Đặt tên theo loại việc: `task/...`, `docs/...`, `stage-x/...`.

   ```bash
   git checkout -b docs/ten-viec
   ```

3. Sửa code, rồi kiểm tra. Chỉ commit khi cả hai lệnh đều pass:

   ```bash
   make lint test
   ```

4. Commit và đẩy nhánh lên:

   ```bash
   git add -A && git commit -m "Mô tả ngắn việc đã làm"
   ```

   ```bash
   git push -u origin docs/ten-viec
   ```

## 3. Pull request, CI và merge (trên web)

1. Sau khi push, GitHub hiện nút **Compare & pull request**. Bấm vào, chọn base là `main`, viết mô tả: đã làm gì, đã kiểm tra gì, còn gì chưa làm.
2. Đợi **CI** (GitHub Actions) chạy `make lint` và `make test` trên Python 3.11 và 3.13. Dấu ✓ xanh mới merge. Dấu ✗ đỏ thì bấm **Details** xem lỗi, sửa trên chính nhánh đó rồi push lại; PR tự cập nhật.
3. Bấm **Merge pull request**, chọn **Create a merge commit**, rồi **Confirm merge**.
4. Bấm **Delete branch** ngay sau khi merge.

Sửa mô tả một PR (ví dụ xoá dòng "Generated by Claude Code"): mở PR, bấm **…** ở góc khung mô tả đầu tiên, chọn **Edit**, sửa rồi **Update comment**.

## 4. Dọn nhánh cũ

**Trên web:** vào tab **Code**, bấm **Branches** (hoặc mở `…/branches`), bấm biểu tượng thùng rác ở từng nhánh, trừ `main`. Xoá nhánh của một PR đang mở thì GitHub tự đóng PR đó.

**Bằng lệnh** (danh sách 21 nhánh cũ tại ngày 2026-11-04, đã kiểm tra là không còn nội dung nào chưa có trên `main`):

```bash
git push origin --delete contract/approve-payment-event docs/handoff docs/project-overview docs/readme docs/stage-c-spec docs/test-results docs/validation-results integration/stage-ab stage-c task/T01-skeleton task/T02-contract-draft task/T03-dataset-manifest task/T04-ieee-cis-adapter task/T05-time-split task/T05b-eda-profiling task/T06-metrics task/T06b-recall-at-fpr task/T07-rule-based-baseline task/T08-logistic-baseline task/T09-run-log-cli task/T10-leakage-guards
```

Xoá luôn bản sao các nhánh đã mất trên máy mình:

```bash
git fetch --prune
```

## 5. Cài đặt nên bật một lần (Settings của repo)

| Cài đặt | Ở đâu | Vì sao |
| --- | --- | --- |
| **Automatically delete head branches** | Settings → General → Pull Requests | Nhánh tự xoá sau khi merge, không còn phải dọn tay |
| **Branch protection cho `main`** | Settings → Branches → Add rule (hoặc Rules → Rulesets), chọn `main`: *Require a pull request before merging* và *Require status checks to pass* (chọn hai job `lint and test`) | Không ai đẩy thẳng lên `main` hay merge khi CI đỏ |
| Chỉ cho phép merge commit | Settings → General → Pull Requests: bỏ chọn *squash* và *rebase* | Lịch sử giữ đúng từng commit như đã kiểm tra |

## 6. Git hook: bỏ dòng ghi công cụ AI khỏi commit

File `.githooks/commit-msg` chạy mỗi lần commit. Nó xoá các dòng `Co-Authored-By: … Claude/Anthropic`, `Claude-Session: …` và `Generated with/by [Claude Code](…)`, giữ nguyên mọi dòng khác (kể cả `Co-Authored-By` của người thật). Có test trong `tests/test_commit_msg_hook.py`.

- Hook chỉ có tác dụng trên máy đã bật nó. `make setup` tự bật; bật riêng thì chạy:

  ```bash
  make hooks
  ```

- Kiểm tra đã bật chưa (phải in ra `.githooks`):

  ```bash
  git config core.hooksPath
  ```

- Hook **không** sửa commit đã có, và không sửa mô tả PR trên GitHub (sửa tay theo mục 3). Lịch sử cũ trên `main` được giữ nguyên theo quyết định của chủ dự án.

## 7. Đánh dấu bản nộp báo cáo (tag)

Khi chốt bản nộp, gắn tag cho commit trên `main` để sau này mở lại đúng phiên bản đó:

```bash
git checkout main && git pull
```

```bash
git tag -a v1.0-bao-cao -m "Bản nộp báo cáo thực tập"
```

```bash
git push origin v1.0-bao-cao
```

Trên web: tab **Releases** → **Draft a new release** → chọn tag, đính kèm file PDF báo cáo.

## 8. Những thứ không bao giờ commit

Dataset (`datasets/raw/`), `artifacts/` (Parquet, run folder, dashboard), file mô hình, `.env`. `.gitignore` đã chặn; CI cũng có bước kiểm tra. Lỡ `git add` nhầm thì gỡ ra trước khi commit:

```bash
git restore --staged <đường-dẫn-file>
```
